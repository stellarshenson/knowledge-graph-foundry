3. **Task - Buffered ontology concept** (v0.1.0): Redesigned the unstructured ingestion pipeline to use an in-memory ontology buffer that evolves during ingestion rather than treating the ontology as a static input file<br>
    **Result**: Added a full Ontology Buffer section to `docs/ingestion-unstructured.md` with five subsections. Buffer initializes from `ontology.yml` (constrained) or empty (free extraction) and tracks entity types with frequency counts, relationship types with source/target constraints, type variant mappings (e.g., "Human" -> "Person"), and per-document coverage scores. The pipeline now has a schema signal extraction pre-flight pass - a lightweight LLM call that detects category signals before full extraction, compared against the buffer to compute coverage. Coverage drives adaptive extraction: high coverage (> 0.8) uses strict type constraints, low coverage (< 0.5) loosens constraints and accepts `NEW_`-prefixed types for review. After each document, extraction results feed back into the buffer - types accumulate with frequency tracking, the LLM checks if new types are variants of existing ones, and relationship patterns are validated for consistency. Refinement triggers on configurable thresholds: every N documents (default 5), on sustained coverage drops, or when candidate types accumulate past a count threshold. At run completion the buffer flushes to `.kg-builder/ontology.yml`, meaning free extraction produces a usable ontology as a side effect and constrained extraction outputs a refined version. Updated `docs/SPEC.md` with `ontology_buffer` config section (refine_every_n_docs, coverage_threshold, min_frequency_to_confirm, flush_on_complete) and revised `kg extract` behaviour description to reflect the adaptive ontology mechanism.
