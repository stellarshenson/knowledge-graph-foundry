# GLiREL - Generalist Model for Zero-Shot Relation Extraction

**arXiv 2501.03172 (2025)**. SoTA zero-shot relation classification on Wiki-ZSL and FewRel: at m=10 unseen relations, F1 83.67 (Wiki-ZSL) and 87.60 (FewRel) with synthetic pretraining, beating TMC-BERT (81.23/85.68) and RelationPrompt (71.5/80.0); on GPU, GLiREL processes roughly 20x more sentences/second than RelationPrompt and TMC-BERT on Wiki-ZSL (47.60 sent/s vs 2.06 and 1.41) - it classifies every entity pair against every candidate label in a single forward pass instead of one pass per pair-label combination.

**Key mechanism**: one bidirectional transformer (DeBERTa V3-large, 467M params total) jointly encodes M zero-shot relation-type labels (each prefixed by a `[REL]` token) and the N-token input text in a single input sequence. Entity start/end token embeddings are concatenated and passed through an FFN to form representations for all N²-N ordered entity pairs (self-pairs excluded); relation labels are projected through their own FFN into the same latent space; optional cross-attention (pair attends to labels, and vice versa) and self-attention refinement layers sharpen both sets of representations (max 2 layers in practice). A scoring layer computes sigmoid(pair-embedding · label-embedding) for every (pair, label) combination, interpreted as the probability that pair (u,v) expresses relation t. The model assumes entities are supplied by an upstream span extractor and focuses purely on typing the relations between them - the paper states this explicitly as a design choice to keep the pipeline flexible.

**Main findings**: at m=10 unseen relations, synthetic pretraining lifts GLiREL over training-from-scratch on both benchmarks; at m=15, GLiREL (Wiki-ZSL F1 73.91, FewRel F1 84.48) edges out the prior leading model TMC-BERT (73.77/81.00) and outperforms GPT-4o at every tested value of m on both datasets. The synthetic training set is built by sampling Fineweb text and annotating every entity pair with Mistral-7B-Instruct-v0.3 (no predefined relation taxonomy) - 63,493 texts, 25,619,624 annotated relations, majority labeled NO_RELATION, filtered to exclude any label overlapping the benchmark test labels to preserve the zero-shot split. Ablations show relation-label random-dropping and refinement layers help on Wiki-ZSL (many entity pairs per instance) but hurt on FewRel (single entity pair per instance, cleaner signal). Extended to document-level RE (Re-DocRED) via a SELF coreference label plus connected-components clustering to merge mentions into entity clusters and propagate relations across the document; GLiREL is competitive with fine-tuned LLM baselines carrying 15x more parameters but is surpassed by specialized DocRE models (LMRC, KD-RoBERTa, DREEAM). Stated limitations: total label count per instance is capped by DeBERTa's 512-token max sequence length, and the N²-N pair count scales quadratically with entities per instance, requiring a token-distance windowing heuristic for long documents.

**Key takeaways for KGF**: direct architectural fit for R47-H513's typed-edge multi-hop coverage layer sitting downstream of GLiNER spans - GLiREL and GLiNER share the same "encode labels and text jointly, classify everything in one forward pass" design, so a GLiNER->GLiREL pipeline reuses that pattern end to end: GLiNER emits N entity spans per chunk, GLiREL scores all N²-N ordered pairs against M zero-shot relation-type labels in a single pass, with labels swappable per query at inference time and no fixed schema or per-candidate LLM call. The exhaustive N²-N enumeration is exactly the coverage guarantee H513 needs over a chunk's entity set, rather than sampled or heuristic pair selection; the tradeoff to plan around is the quadratic pair count and the 512-token joint sequence budget shared between text and label list, both of which cap how many labels/entities can be scored per chunk before windowing is required.
