**Self-Refine: Iterative Refinement with Self-Feedback (2023)**

A single LLM plays generator, critic, and refiner in a loop with no additional training, fine-tuning, or reinforcement learning. Across **7 diverse tasks** with GPT-3.5, ChatGPT, and GPT-4, Self-Refine improves task performance by **~20% absolute on average**, with the largest gains on preference-scored tasks (Dialogue Response Generation jumps from 25.4% to 74.6% GPT-4 preference, a **49.2 pp** gain) and the smallest on Math Reasoning, where the critic frequently cannot tell an answer is wrong.

**Key mechanism**
- Three-step loop using the same model M throughout: (1) generate an initial output, (2) prompt M to critique its own output and produce feedback, (3) prompt M to refine the output given that feedback; repeat until a stopping condition
- No external verifier, no ground truth, no separate reward model - feedback is entirely self-generated by the same LLM instance
- Applied unmodified across heterogeneous tasks: dialogue response generation, code optimization, code readability, math reasoning, constrained generation, sentiment reversal, acronym generation

**Main findings**
- GPT-4 + Self-Refine improves Code Optimization from 27.3% to 36.0% (**+8.7 pp** absolute)
- Constrained Generation shows some of the largest gains because a first attempt frequently misses some of the up-to-30 required concepts, giving the critic concrete, checkable errors to find
- Dialogue Response Generation: GPT-4 preference score rises from 25.4% to 74.6% (**+49.2 pp**)
- Math Reasoning shows only modest gains, because ChatGPT's self-generated feedback says "everything looks good" on **94%** of instances even when the answer is wrong; gains jump to 5%+ only when an external source flags whether the current answer is actually incorrect
- Improvement holds across all three base model sizes tested, with GPT-4 + Self-Refine generally outperforming GPT-3.5 and ChatGPT + Self-Refine even on tasks where base GPT-4 started behind them

**Key takeaways**
- Self-Refine's headline "~20% average gain" is not uniform - it concentrates heavily on tasks where the model's self-critique has a concrete error surface to check against (missing concepts, awkward phrasing, unoptimized code) and nearly vanishes on tasks (math) where the model cannot reliably self-detect that it is wrong
- The paper's own ablation is the clearest evidence: adding one bit of external correctness signal to the Math Reasoning critic step recovers gains the pure self-critique loop could not find on its own
- The pattern generalizes as a design rule: an extract-critique-fix loop is only as good as the critic's actual detection ability on that task, independent of how well the loop is engineered

**Relevance**
- Establishes the canonical extract-critique-fix loop pattern that any KGF self-repair pass (H563-style) is a variant of
- Directly predicts the risk the grounded-critique ablation is testing: a critique step without real signal (as in Math Reasoning here) yields negligible gains and can be a wasted pass, so KGF's repair loop needs a critic with genuine detection power over its target error class, not just an LLM asked to "check your work"
