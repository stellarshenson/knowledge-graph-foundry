# Claude Code Journal

This journal tracks substantive work on documents, diagrams, and documentation content.

1. **Task - CLI specification document** (v0.1.0): Created `docs/SPEC.md` defining the full CLI command structure, configuration, and data formats for kg-builder-cli<br>
    **Result**: Spec covers six typer subcommands (`init`, `extract`, `load`, `pipeline`, `schema`, `status`). The `.kg-builder/` directory is the resource folder for the target project - contains `config.yml` (Neo4J connection, LLM settings, extraction/loading defaults), `ontology.yml`, `schemas/` for structured data descriptions, and `extractions/` for output. Supports both structured (JSON/JSONL with generatively-interpreted schema descriptions) and unstructured (PDF/TXT/MD/DOCX with chunking) data sources. `kg init` has template mode (commented YAML scaffold) and interactive mode (LLM-driven Q&A to generate tailored config). Config resolution: CLI flags > config.yml > built-in defaults. Secrets use `${VAR}` interpolation from `.env`. Added Neo4J LLM Graph Builder as reference implementation in `README.md`.

2. **Task - Ingestion strategy documents** (v0.1.0): Created `docs/ingestion-unstructured.md` and `docs/ingestion-structured.md` describing detailed ingestion pipelines<br>
    **Result**: Cloned neo4j-labs/llm-graph-builder reference implementation and studied its extraction pipeline - LLMGraphTransformer usage, token-based chunking with SHA1 chunk IDs, APOC merge-based dedup, `__Entity__` base label pattern, backtick cleanup, and deadlock retry logic. Extracted text from all 6 reference PDFs using pymupdf. Key insights incorporated: from Dynamic Ontology article (Akash Goyal) - schema-first extraction with separate normalization layer storing `normalized_uri`/`normalized_label`/`normalized_score`/`normalized_method` on resolved entities, coverage scoring as a governance signal for ontology drift detection, and keeping curated schema small to reduce extraction errors. From Brian Curry's end-to-end guide - 6-phase pipeline (acquisition, entity extraction, relationship extraction, entity resolution/linking, storage, querying), hybrid extraction combining spaCy + GliNER + LLM, coreference resolution for pronouns, entity linking to knowledge bases (Wikidata/DBpedia via Relik), and LLM-based entity clustering for custom graphs. Unstructured doc covers: document parsing, token-based chunking, free vs constrained LLM extraction with prompt templates, chunk batching, intra/cross-document dedup, LLM-based entity resolution with clustering prompt, ontology schema consolidation for type sprawl, Neo4J graph structure with Document/Chunk/Entity nodes, and batch Cypher loading with indexing. Structured doc covers: schema description formats (markdown/YAML/text interpreted generatively), LLM mapping prompts, record batching with auto-sizing, deterministic entity IDs from field values, entity normalization pass, ontology interaction, hybrid scenarios with mixed structured/free-text fields, and Source node provenance instead of Chunk nodes.
